Input: 2,147,483,648 bytes (2 GiB) of split complex input
f64: 2^27 points, matrix 2048 x 65536

Conclusion:
The new SIMD kernels really do emit and select AVX-512, but do not provide a
consistent whole-FFT improvement on this host. f64 is slower; the small f32
median difference is below the run-to-run spread. Keep scalar packed tiles
as the default. Both SIMD load strategies remain available for experiments.

Variants (FOUR_PASS_TRANSPOSE):
- scalar: the committed packed scalar transpose, default.
- simd: packed tiles followed by register transposes, 8x8 f64 / 16x16 f32.
- direct: same register transpose, loaded directly from the source matrix.
All preserve the optimized matrix dimensions, 16-column gather batches,
128-column transpose bands, 32-row tiles, FFT kernels and twiddle generation.
The SIMD permutation uses three interleave stages for f64 and four for f32.
Everything remains safe Rust, using fearless_simd runtime dispatch with
inline(always) on the SIMD implementation below the dispatch boundary.

Disassembly:
See four_pass_simd_disassembly.txt for named transpose wrapper symbols,
ZMM instruction counts and selected loads, permutations and stores.
f64 emits vpermt2pd; f32 emits vpermt2ps, using 512-bit ZMM registers.
Runtime logs select Avx512 for the actual 2 GiB executions.
These checks inspect the transpose functions, not merely the FFT kernels.

A separate explicit constant-index shuffle network was also tested. LLVM
lowered that version to gathers and substantial stack traffic rather than
the intended compact unpack/shuffle sequence; it did not improve timings
and was discarded. The retained experiment uses the cleaner interleave network.

Final comparison method:
- Same final release executable for scalar and SIMD, selected at planning time.
- No profiling, compilation or tests overlapped these timing runs.
- f64 process order: scalar A, SIMD A, SIMD B, scalar B.
- f32 process order: SIMD A, scalar A, scalar B, SIMD B.
- Each process warms up once, then measures 5 transforms: 10 samples per mode.
- Same seeded input regenerated outside timing before every transform.
- Allocation, page touching, planning and input generation excluded.
- four-pass-only mode, approximately 4 GiB resident data/scratch plus small plans.
- Separate both-mode runs at 2 GiB validate 4096 output bins against DIT.

Invocation for each block (select MODE=scalar or simd):
