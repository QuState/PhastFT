Method:
- Forward complex-to-complex FFT, natural-order input and output.
- One untimed warm-up per implementation, then 10 measured transforms each.
- Alternate which implementation runs first in each measured pair.
- Same seeded random input regenerated before every transform, outside timing.
- Exclude allocation, planning, input generation and initial page-touching.
- Four-pass output remains in scratch; no copy back is included or required.
- Retain DIT plan, four-pass plan, input and scratch in both mode (~6 GiB).
- Each implementation separately needs about 4 GiB at these input sizes:
  DIT uses ~2 GiB of twiddles; four-pass uses 2 GiB scratch and small plans.
- Timings are from one host and one session, not a hardware-independent claim.

Algorithm:
1. Gather 16 adjacent columns per task, run local DIT FFTs, apply twiddles.
2. Tiled transpose (32 x 32).
3. Contiguous local DIT FFTs.
4. Tiled transpose into natural frequency order in scratch.
Four denotes full-array sweeps, not literal DRAM transactions: local FFTs
make multiple cache passes. Twiddles use f64 recurrence, restarted every 256
values. Plans take O(sqrt(N)) space. Execution is allocation-free and safe Rust.
SIMD uses the existing DIT dispatch/vectorize entry points; the new scalar
loops do not introduce additional fearless_simd inlining boundaries.
