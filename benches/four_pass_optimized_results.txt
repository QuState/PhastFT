Four-pass FFT optimization results

Date: 2026-10-21
Baseline: commit 7d098a4 (original prototype, saved release binary)
Optimized: follow-up changes to examples/support/four_pass.rs
CPU: AMD Ryzen 9 9950X, 16 cores / 16 online logical CPUs
RAM: 30 GiB; governor: powersave; affinity not pinned
OS: Linux 6.8.0-138-generic, x86_64
Compiler: rustc 1.99.1 (58cf8f9c3 2026-10-13)
Build: cargo build --release --offline --example benchmark_four_pass
Features: default (parallel); no RUSTFLAGS override
Threads: RAYON_NUM_THREADS=16
Input: 2,147,483,648 bytes per transform (2 GiB), split complex arrays
f64: 2^27 points; f32: 2^28 points

Retained changes:
- Change rows from 2^(floor(log2(N)/2)) to
  2^max(floor(log2(N)/2)-2, 0). Both dimensions remain O(sqrt(N)).
  At 2 GiB: 2048 x 65536 (f64), 4096 x 65536 (f32).
  The first-pass batch shrinks from 2 MiB to 512 KiB, fitting in the
  1 MiB per-core L2 with room for the local FFT and its small twiddle plan.
- Widen full-transpose destination bands from 32 to 128 columns to
  amortize source page walks.
- Copy source tiles contiguously to a packed stack buffer before transposing.
  Process real and imaginary components separately to reduce cache-set
  conflicts. Full transpose tiles are 32 x 128; gather tiles are 32 x 16.
  The largest stack buffer is 32 KiB per worker for f64.
- Share the tile helper between the initial gather and full transposes.
- Add optional FOUR_PASS_PROFILE=1 pass timing and print matrix dimensions.

The algorithm still has four full-array sweeps, natural-order output in
scratch, normalized inverse transforms, safe Rust and no execution-time heap
allocation when profiling is disabled. Scratch remains one extra input-sized
complex array; planning is O(sqrt(N)). The public library API is unchanged.

Explicit SIMD transposes and eight-lane f64 twiddle recurrences were tried
with dispatch! and inline(always) as prescribed by fearless_simd's manual.
Neither gave a consistent end-to-end improvement, so neither is retained.
The final implementation uses the existing DIT SIMD dispatch boundaries.
Fusing the middle transpose and row FFTs also did not improve total time.

Final comparison method:
- Original executable copied before edits; optimized executable built after
  correctness tests. No compilation or tests overlapped timed runs.
- Sequential order: original f64, optimized f64, original f32, optimized f32.
- Original: 5 measured runs per algorithm. Optimized: 10 measured runs.
- Each invocation has one untimed warm-up per algorithm and alternates
  DIT/four-pass order in measured pairs.
- Identical seeded random input regenerated outside timing for every FFT.
- Planning, allocation, initial page-touching and input generation excluded.
- FOUR_PASS_PROFILE unset for all final comparison runs.
- Each process retains both plans and scratch (approximately 6 GiB).
- Both modes compare 4096 distributed output bins against DIT at 2 GiB.
- These are single-host results. The matrix split was tuned for these sizes;
  performance on other hardware, sizes and thread counts is not established.

Commands (run sequentially):
