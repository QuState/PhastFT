Dispatched scalar transpose: AVX-512 disassembly

Historical experiment: the dispatch wrapper, forced inlining and auto mode
were subsequently removed. This disassembly describes the measured experimental
binary identified below, not the current source.

Build: cargo build --release --offline --example benchmark_four_pass
No RUSTFLAGS or target-cpu override.
Command: objdump -d -C -Mintel target/release/examples/benchmark_four_pass
Binary SHA-256: 18ab282fe31d87df3bcff0b32c22ae8d602c87024b6ea0478cabf3d736ea1c60

Experiment: mark the original generic scalar transpose_columns loop
#[inline(always)] and call it inside fearless_simd::dispatch!(Level::new(), ...).
The loop, packing buffer, indexing, tiling and matrix dimensions are unchanged.
No vector types, intrinsics or hand-written shuffles appear in this variant.

LLVM vectorizes the transposed reads as gathers from the packed stack tile:
- f64: vgatherqpd zmm (eight doubles), followed by vmovupd zmm stores.
- f32: two vgatherqps ymm (eight floats each, with 64-bit indices in zmm),
  vinsertf64x4 to combine them, then a vmovups zmm store (16 floats).
This is AVX-512 code but does not form the hand-written register transpose.
The hand-written implementation instead uses contiguous full-width loads
and vpermt2ps/pd permutations in registers.

Tile initialization is still present, using 512-bit vmovdqu64 stores;
packing may call memcpy. SIMD feature availability alone does not eliminate
packing or initialization, or guarantee that gather vectorization is faster.

The following are excerpts from the named dispatch wrappers, including
all instructions around the first gather loop. Counts are static, not dynamic.
